# 메아리 발자국 — 4차 설계 (프로덕션 디자인실)

기준: `GAME_DESIGN.md` v4. 3차 빌드를 대표가 플레이한 결과에서 출발한다.

## 대표 메모와 해석

원문(합격 메모):
> 아직 아트가 들어가지 않은 걸 고려해도 게임이 너무 심심하게 보여요 게임 해결자체는 단순하지 않지만요

| 문장 | 분류 | 대응 |
| --- | --- | --- |
| 아트가 들어가지 않은 걸 고려해도 | 설계로 풀 것 | "그림이 없어서"가 원인이 아니라는 뜻이다. 그림 없이도 고칠 수 있는 것을 찾는다(아래 재현) |
| 너무 심심하게 보여요 | **설계로 풀 것** + 구현 | GAME_DESIGN 12절 "보는 맛"(대기 중 움직임, 질감, 타격감), 14절 "보는 맛 기준". 4차의 전부 |
| 게임 해결 자체는 단순하지 않지만요 | 그대로 둘 것 | 규칙·난이도·층은 건드리지 않는다. 이번 차수 규칙 변경 0 |

로드맵의 4차(저장/재개, 일시정지, 층 소개, 층 선택)는 5차로 미뤘다. 메모가 로드맵과 부딪치면 메모가 먼저다.

## 이번 차수 범위

넣을 것 (전부 화면. 규칙·입력·콘텐츠·테스트 인터페이스의 기존 뜻은 그대로)
1. **대기 중의 움직임** — 12절 "보는 맛" 가
2. **보드와 화면의 질감** — 12절 "보는 맛" 나 (타이틀의 움직이는 그림 포함)
3. **타격감** — 12절 "보는 맛" 다 (화면 흔들림, 조각, 충격 고리, 잔상, 연속 처치, 층 클리어)
4. 이전 대조표의 △ 가운데 연출로 풀리는 것: 폭탄이 날아가는 움직임, 던지기 대상 표시, 으깨기가 가리는 것

미룰 것
- 저장/재개, 일시정지, 층 소개, 층 선택 → 5차
- 아트(그림) → 결정 요청 `visual_plan`에 따라
- 사운드 → 6차

로드맵과 달라진 점과 이유
- 4차를 통째로 바꿨다. 화면이 심심한 채로 저장·층 선택을 더해도 대표가 본 문제는 그대로 남는다.
- 연출은 원래 "규칙이 고정된 뒤"(마지막 차수)에 두었는데 앞당겼다. 규칙은 3차까지 세 번의 플레이로 굳었고(대표: 해결은 단순하지 않다), 이번에 정의한 움직임은 개체 단위라 그림이 붙어도 다시 만들지 않는다.

## 규칙 변경과 근거

**바꾼 규칙은 없다.** 시뮬레이션도 더하지 않았다(`sim.py` 그대로).

### 보는 맛 (추가 — GAME_DESIGN 12절 "보는 맛", 14절 "보는 맛 기준")
- 무엇을: 대기 중 움직임 8종, 질감 5가지, 타격감 13가지. 전부 표시이고 규칙 상태에 영향이 없다.
- 왜: "심심하다"를 재 보니 움직임 0%, 평평한 두 색 85~96%였다. 그림이 없어도 고칠 수 있는 원인이다.
- 숫자(전 → 목표). 시뮬레이션 대신 `visual_audit.py`로 잰다.

| 기준 | 전(3차 빌드) | 목표(4차 빌드) |
| --- | --- | --- |
| 대기 중 움직임(0.5초) | 0% | 0.5% 이상 |
| 플레이 화면 두 색 비율 | 85~96% | 75% 이하 |
| 타이틀·결과 화면 두 색 비율 | 97~98% | 85% 이하 |
| 처치 순간에 동시에 일어나는 연출 수 | 3 | 6 이상 |
| 한 턴 연출 길이 | 0.72~0.80초 | 0.9초 이하 |

- 버린 대안: (가) 색을 늘려 화려하게 — 강조색 둘(청록, 주황)로 위험과 메아리를 읽는 설계가 흐려진다. (나) 한 턴 연출을 길고 크게 — 계획 게임의 속도를 죽인다. (다) 규칙을 더해 화면에 일이 많이 일어나게 — 대표는 해결이 단순하지 않다고 했다. 문제는 규칙이 아니다.
- 남은 의문: 이 숫자는 "심심하지 않다"의 필요조건일 뿐이다. 살아 보이는지는 대표가 봐야 안다. 움직임이 의도 읽기를 방해할 수도 있다(16절).

## 기획실에 넘기는 메모

- **기존 콘텐츠의 정답은 달라지지 않는다.** 규칙·층·테스트 인터페이스의 기존 뜻을 바꾸지 않는다. 기존 검사 M1~M25는 한 글자도 바뀌지 않아야 한다(이번 차수의 "바뀐 기존 검사"는 없어야 정상).
- **무엇을 검사로 쓸 수 있는가**(화면은 규칙 검사로 볼 수 없다. 그래서 아래 세 겹으로 나눠 달라)
  1. 검사(smoke.gd)로: 연출이 규칙을 건드리지 않는다는 것 — 한 턴 연출 길이 ≤ 0.9초, 연출 중 입력 정책, 흔들림이 입력 좌표에 영향을 주지 않음, "어떤 사건에 어떤 연출이 붙는가"의 배선(사건 → 연출 이름 목록을 읽을 수 있는 테스트 인터페이스가 있으면 검사할 수 있다).
  2. 스크린샷과 `visual_audit.py`로: 14절 "보는 맛 기준"의 숫자. 대기 중 움직임은 같은 장면을 0.5초 간격으로 찍은 두 장(`…idle-a`, `…idle-b`)이 필요하다.
  3. 대표의 눈으로: 살아 보이는가, 정신없는가.
- **함정**
  - 헤드리스 검사에서는 그리기가 돌지 않는다. 연출의 상태(시각, 목록)는 그리기 함수 밖에서 계산되어야 검사가 읽을 수 있다.
  - 화면 흔들림은 보드와 그 위의 것만. 글자·버튼·입력 좌표는 고정.
  - 대기 중 움직임은 시간(시계)으로만 정해져야 한다. 난수를 매 프레임 뽑으면 스크린샷이 찍을 때마다 달라져 `shots_diff` 비교가 어려워진다 — 입자 위치도 시계의 함수로.
  - 기존 스크린샷은 **전부** 달라진다(질감이 바뀌므로). `shots_diff`의 "달라진 영역"으로는 회귀를 가릴 수 없으니, 이번 차수의 회귀 확인은 "파일 이름이 말하는 화면이 그대로 찍혀 있는가"를 장마다 눈으로 보는 것이다.
  - 연출을 더해도 한 턴의 시간표(이동 0.12 → 메아리 0.14 → 멈칫 0.08 → 적 0.26 → 여운 0.20)는 늘리지 않는다.
