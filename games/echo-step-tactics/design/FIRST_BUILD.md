# 메아리 발자국 — 첫 빌드 기획 v1

기준: `GAME_DESIGN.md` v1, `ROADMAP.md` "첫 빌드 후보". 이 문서가 이번 빌드의 기준이다.
규칙의 기준 구현은 `design/sim/sim.py`의 `Game` 클래스다(이번 빌드는 그중 졸개·궁수만 쓴다). 이 문서와 sim.py가 다르게 읽히면 sim.py가 옳다.

검증하려는 것(아이디어 연구소의 질문): **지금의 한 수가 3턴 뒤의 공격이 되는 것을, 설명 없이 읽고 노리게 되는가.**

### 한 턴 (행동 하나를 확정하면 아래를 이 순서로 전부 처리한다)

용어: `hist[k]` = k번째 턴에 플레이어가 행동한 뒤의 (위치, 행동). `hist[0]` = (시작 칸, 시작). `turn` = 이 층에서 끝난 턴 수.

0. **행동 가능 여부** — 불가능하면 턴을 쓰지 않는다(아무것도 바뀌지 않음).
   - 이동: 도착 칸이 보드 안, 벽 아님, 적 없음. (메아리 칸으로는 갈 수 있다)
   - 베기: 대상 칸(현재 칸 + 방향)이 보드 안이고 벽이 아님. (적이 있든 없든 가능)
   - 대기: 항상 가능.
1. `turn += 1`. 이동이면 플레이어를 옮긴다. `hist`에 (위치, 행동)을 추가한다. 플레이어는 지금 어떤 피해도 주지 않는다.
2. **메아리 재생**: `k = turn − 3`. `k ≥ 1`이면 메아리가 `hist[k]`를 재생한다.
   - 이동이었으면 **밟기**: `hist[k].위치`에 적이 있으면 처치 (`kills.stomp += 1`).
   - 베기 D였으면 **베기**: `hist[k].위치 + D`에 적이 있으면 처치 (`kills.slash += 1`).
   - 대기였으면 아무것도 안 함.
   - 이번 턴의 메아리 칸 `ep = hist[k].위치` (`k < 1`이면 메아리 없음).
3. **적 행동**: 살아 있는 적을 id 오름차순으로, 턴 시작 때 공개된 의도대로 실행한다. 의도는 플레이어 행동을 보고 바뀌지 않는다.
   - 이동(dir): 도착 칸이 보드 안, 벽 아님, `ep` 아님, 플레이어 아님, 다른 적 없음이면 이동. 아니면 제자리.
   - 치기(dir): `적 칸 + dir`에 플레이어가 **지금** 있으면 체력 −1.
   - 조준(dir): 적 칸에서 dir로 한 칸씩 나아가며 — 보드 밖이나 벽이면 멈춤 / `ep`면 멈춤(막음) / 적이 있으면 그 적 처치(`kills.friendly += 1`) 후 멈춤 / 플레이어면 체력 −1 후 멈춤.
   - 의도 없음: 아무것도 안 함.
4. **증원**:
   - `turn ≥ 30`이고 `(turn − 30) % 3 == 0`이고 적이 1 이상이면 예고 목록 끝에 (turn + 1, 졸개, (3,0)) 추가.
   - 예고 목록을 앞에서부터: 예고 턴 ≤ turn이면 — 그 칸에 플레이어·`ep`·적이 없으면 등장(새 id = 지금까지 쓴 id 다음 번호), 있으면 예고 턴을 +1 해서 남김.
5. **판정** (이 순서): 체력 ≤ 0 → 패배. 적 0이고 예고 0 → 층 클리어. `turn == 60` → 패배.
6. 계속이면 **다음 턴의 의도를 계산해 공개**한다(아래).

### 의도 계산 (층 시작 때, 그리고 매 턴 끝에)

`occ` = 모든 적의 칸 + 지금 메아리 칸(`turn − 3 ≥ 1`이면 `hist[turn − 3].위치`).

- **졸개**
  - 플레이어와 맨해튼 거리 1이면 → 치기(플레이어 쪽 방향).
  - 아니면 → 길 찾기(아래)의 첫 걸음 방향으로 이동. 길이 없으면 의도 없음.
- **궁수**
  - 방향 순서대로 네 방향을 본다. 바로 옆 칸이 플레이어면 그 방향은 건너뛴다(최소 사거리 2). 그 방향으로 한 칸씩 나아가며 보드 밖·벽·적·메아리 칸을 만나기 전에 플레이어 칸에 닿으면 → 조준(그 방향).
  - 조준할 방향이 없고 플레이어와 맨해튼 거리가 2 이상이면 → 길 찾기의 첫 걸음 방향으로 이동. 길이 없으면 의도 없음.
  - 플레이어와 붙어 있으면(거리 1) → 의도 없음.
- **길 찾기** (sim.py `bfs_step`): 적 칸에서 플레이어 칸까지 너비 우선 탐색. 이웃은 방향 순서대로 넣는다. 벽과 `occ`(자기 칸 제외)는 지날 수 없고, 플레이어 칸은 도착점으로만 들어간다. 각 칸은 처음 발견된 경로만 기억한다. 찾은 경로의 첫 걸음 방향을 돌려준다.

### 층과 런
- 층 시작: 플레이어를 시작 칸에, 적을 배치 순서대로 id 0, 1, 2 …로 놓는다. `turn = 0`, `hist = [(시작 칸, 시작)]`, 메아리 없음. 의도 계산.
- 층 클리어: 마지막 층이면 승리(결과 화면). 아니면 체력 = min(5, 체력 + 1) 후 다음 층 시작.
- 패배: 결과 화면. 결과 화면에서 탭하면 1층부터 새 런(체력 5, 처치 수 0).
- `kills`는 런 단위로 누적한다.

## 콘텐츠

세 층 모두 시작 칸 (3,6). 정답 순서는 `python3 design/first_build_replay.py`가 sim.py로 구한 것이며 tests/smoke.gd가 그대로 재생한다.

### 1층 「첫걸음」
- 벽: (1,1) (5,1) (1,5) (5,5)
- 적: 졸개 (3,0), 졸개 (0,2)
- 증원: 6턴 졸개 (6,0)
- 정답(11턴, 피해 0): `U SU SL SL R U R SR SU SR W`

### 2층 「궁수의 복도」
- 벽: (2,2) (2,3) (2,4) (4,2) (4,3) (4,4)
- 적: 궁수 (3,0), 졸개 (0,0), 졸개 (6,0)
- 증원: 8턴 졸개 (0,6)
- 정답(12턴, 피해 0): `L L U SU R L SL SR SR SR SR SU`

### 3층 「두 개의 사선」
- 벽: (1,2) (5,2) (3,3)
- 적: 궁수 (0,0), 졸개 (3,0), 궁수 (6,1)
- 증원: 5턴 졸개 (0,3), 9턴 졸개 (6,4)
- 정답(12턴, 피해 0): `U R SU SR SU SU SU SU SR SR SR U`

세 층을 정답 순서로 깨면: 승리, 체력 5, 처치 밟기 1 · 베기 11 · 오사 0.

## 상태 흐름

| 상태 | 들어오는 조건 | 나가는 조건 |
| --- | --- | --- |
| TITLE | 앱 시작 | 화면 탭 → PLAY (1층, 체력 5, 처치 0) |
| PLAY | 런 시작, 다음 층 | 마지막 층 클리어 → RESULT(승리) / 패배 → RESULT(패배) |
| RESULT | 승리 또는 패배 | 화면 탭 → PLAY (1층부터 새 런) |

- 연출(이동 미끄러짐, 히트스톱 등)은 PLAY 안에서만 일어나는 **표시**다. 게임 규칙 상태는 행동을 확정하는 즉시 한 번에 끝까지 계산하고, 화면은 그 결과를 따라 재생한다. 연출 중 들어온 입력은 버린다.

## 테스트 인터페이스

메인 씬(`res://scenes/main.tscn`의 루트 스크립트)이 아래 이름·타입 그대로 제공한다. tests/smoke.gd는 이것만 쓴다.

읽기
| 이름 | 타입 | 의미 |
| --- | --- | --- |
| `State` | enum `{ TITLE, PLAY, RESULT }` | |
| `state` | int | 현재 상태 |
| `floor_index` | int | 현재 층(0부터) |
| `floor_count` | int | 이번 런의 층 수(기본 3) |
| `turn` | int | 이 층에서 끝난 턴 수 |
| `hp` | int | 플레이어 체력 |
| `player` | Vector2i | 플레이어 칸 |
| `echo_active` | bool | 이번 턴에 메아리가 있었는가(`turn − 3 ≥ 1`) |
| `echo_pos` | Vector2i | 메아리 칸(`echo_active`일 때만 의미) |
| `enemies` | Array[Dictionary] | id 오름차순. 각 항목 `{"id": int, "kind": "W" 또는 "A", "pos": Vector2i, "intent": "move"/"hit"/"aim"/"none", "dir": Vector2i}` (`intent`가 "none"이면 `dir`은 `Vector2i.ZERO`) |
| `spawns_pending` | int | 남은 증원 예고 수 |
| `footprints` | Array[Dictionary] | 앞으로 메아리가 할 일, 빠른 순. 각 항목 `{"pos": Vector2i, "act": String, "in": int}` — `in`턴 뒤(1~3)에 `pos`에서 `act`를 재생. 턴 0에는 비어 있고, 3턴이 지나면 항상 3개 |
| `kills` | Dictionary | `{"stomp": int, "slash": int, "friendly": int}` 런 누적 |
| `last_action` | String | 이번 런에서 마지막으로 확정된 행동. 새 런을 시작하면 "" |
| `result_won` | bool | RESULT일 때 승리 여부 |

행동 문자열: 이동 `"U" "R" "D" "L"`, 베기 `"SU" "SR" "SD" "SL"`, 대기 `"W"`.

입력 흉내
| 이름 | 동작 |
| --- | --- |
| `debug_tap(pos: Vector2) -> void` | 화면 좌표 pos를 한 번 탭(누르고 같은 자리에서 뗌)한 것과 같다 |
| `debug_swipe(from: Vector2, to: Vector2) -> void` | from에서 누르고 to에서 뗀 것과 같다. 실제 터치 입력과 같은 처리 경로를 탄다 |
| `debug_press(id: String) -> void` | 화면 버튼을 누른 것과 같다. `"slash"` = 베기 토글, `"wait"` = 대기 버튼 |
| `debug_act(action: String) -> bool` | PLAY에서 행동 하나를 즉시 확정하고 한 턴을 끝까지 계산한다(연출을 기다리지 않는다). 불가능한 행동이거나 PLAY가 아니면 false를 돌려주고 아무것도 바꾸지 않는다 |
| `debug_load_floors(floors: Array) -> void` | 층 목록을 주어진 것으로 바꿔 새 런을 시작한다(PLAY, 0층, 체력 5, 처치 0). 이 목록은 그 런에만 쓰이고, 결과 화면에서 다시 시작하면 기본 3개 층으로 돌아간다 |

층 데이터 형식(기본 층도 같은 형식으로 둔다):
```gdscript
{
  "walls": [Vector2i(1, 1), ...],
  "start": Vector2i(3, 6),
  "enemies": [["W", Vector2i(3, 0)], ["A", Vector2i(0, 0)]],   # 이 순서대로 id 0, 1, ...
  "spawns": [[6, "W", Vector2i(6, 0)]],                         # [예고 턴, 종류, 칸]
}
```

`debug_swipe`, `debug_press`, `debug_tap`으로 확정된 행동도 `debug_act`와 같은 규칙 함수를 불러야 하고, 검사에서는 호출 직후 결과가 읽혀야 한다(연출과 무관하게 규칙 상태는 즉시 갱신).

## 빌드실에 주는 메모

- **규칙과 표시를 나눈다.** 규칙은 순수한 데이터 계산(한 턴 = 함수 하나)으로 만들고, 화면은 "이번 턴에 일어난 일 목록"을 받아 재생한다. 검사는 규칙만 본다.
- **sim.py와 한 줄씩 대조한다.** 특히 틀리기 쉬운 곳:
  - 의도는 턴 **끝**에 계산해 다음 턴 시작에 공개한다. 실행할 때 다시 계산하지 않는다.
  - 의도 계산의 메아리 칸은 "방금 끝난 턴의 메아리 칸", 실행할 때 막는 메아리 칸은 "이번 턴의 메아리 칸"이다. 서로 다른 칸이다.
  - 길 찾기 동점은 방향 순서(위·오른쪽·아래·왼쪽)와 "처음 발견된 경로"로 정해진다.
  - 궁수 사선은 다른 적과 메아리에 막힌다(의도 계산 때). 그래서 사선에 다른 적이 **나중에** 들어오면 오사가 난다.
  - 증원 예고는 턴 30이 끝날 때 추가되어 턴 31이 끝날 때 등장한다.
- 정답 재생 검사(M9)는 위 규칙이 sim.py와 완전히 같아야만 통과한다. 어긋나면 `python3 design/first_build_replay.py`의 출력과 턴별로 비교해 찾는다.
- 한 손 조작: 보드는 화면 위쪽, 입력은 화면 어디서나. 미리보기는 손가락을 누르고 있는 동안만 보인다.
- 도형만으로 구분되어야 한다(디자인 14절): 플레이어 흰 원, 메아리 반투명 원 + 점선 외곽, 졸개 정사각형, 궁수 삼각형(조준 방향을 가리킴), 벽은 꽉 찬 사각형.
- 글자는 `res://assets/fonts/NotoSansKR-Medium.ttf`. 원 숫자 ③②①은 폰트에 있다.

## 기획실 관찰 (대표 플레이테스트에서 볼 것)

- sim.py로 보면 세 층은 **베기만으로 피해 없이** 깨진다(정답 처치: 베기 11, 밟기 1). 한 수 앞만 보는 봇도 12~13턴에 깬다. 디자인 문서가 "1~3층은 쉽다"고 한 범위 안이지만, 이번 빌드의 질문("발자국이 함정이 되는가")에는 밟기가 거의 필요 없다는 뜻이기도 하다.
- 그래서 플레이테스트 질문을 이렇게 둔다:
  1. 설명 없이 첫 처치를 몇 턴 만에 내는가(목표 12턴 안), 그것이 밟기인가 베기인가.
  2. 제자리에서 베기만 반복하는 플레이가 재미있는가, 지루한가. 지루하면 2차 빌드에서 방패병(정면 베기 무효)을 앞당기거나 디자인실에 반송한다.
  3. 궁수의 화살을 메아리로 막는 순간을 스스로 만들어 내는가.
